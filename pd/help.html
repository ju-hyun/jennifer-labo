1. システム概要

本ツールは JENNIFER5 が収集した X-View トランザクション点データを OpenAPI 経由で取得し、 応答時間の分布を可視化します。集計済みの平均値を扱う「性能トレンド分析 (PTA)」とは異なり、 個々のトランザクション 1 件 1 件を 1 つの点として扱います。

なぜ平均値では不十分なのか

平均応答時間 150ms のシステムでも、P99 が 800ms であれば 100 リクエストに 1 回は 5 倍以上遅い体験が発生しています。 平均値は分布の裾 (テール) を隠してしまうため、実際のユーザ体験を代表しません。 SLA / SLO は平均ではなくパーセンタイルで定義すべきです。

データ取得の仕組み

X-View データの取得には OpenAPI の /api/transaction/time を使用します。 この API は仕様上 1 回の照会で最大 1 分間しか取得できないため、 指定した期間を 1 分単位のチャンクに分割し、逐次 (同時実行数 1) で取得します。

X-View の照会は JENNIFER のデータサーバに負荷をかけます (マニュアル付録 5.9.4.5 に明記)。 意図的に並列化していないのはこのためです。期間はできる限り絞り込んでご利用ください。

「直近 N 分」のプリセットは、「照会」ボタンを押した時点の現在時刻で期間を取り直します (画面を開いたまま時間が経っても、古い区間を照会することはありません)。 照会回数が 120 回 (= 120 分) を超える場合は、実行前に確認ダイアログを表示します (config.js の CONFIRM_CHUNKS で変更可能)。

隣り合うチャンクは境界の時刻を共有します。API が境界時刻を両側で含む場合、境界で終了したトランザクションが 2 回返されることがあるため、直前のチャンクと txid が同じ行は自動的に除外し、 除外した件数を画面に通知します。

期間の時刻は JENNIFER サーバの時間帯 (config.js の TIMEZONE。配布時の既定は Asia/Tokyo) で指定・表示します。入力欄の横に JST などと表示されます。 ブラウザの時間帯がサーバと異なる場合 (例: 海外から日本のサーバを見る場合) でも、サーバ基準の時刻で照会されます。 TIMEZONE を空にすると、従来どおりブラウザのローカル時刻になります。

絞り込み実行場所理由

2. メインヒストグラム

横軸が応答時間の区間 (ビン)、縦軸がその区間に入ったトランザクション件数です。 分布の「形」からシステムの性質を読み取ります。

分布の形の読み方

形状意味次のアクション
左に鋭いピーク + 右にロングテール 正常な Web システムの典型。大半は速く、一部だけ遅い テールの原因 (GC / ロック / 遅い SQL) を特定
山が 2 つ (二峰性 / bimodal) 2 種類の処理が混在。キャッシュヒット/ミス、正常系/異常系など アプリケーション名で絞り込んで山を分離
全体的に平坦で広い 応答時間が安定していない。負荷やリソース競合の可能性 PTA で同時刻の CPU・TPS 推移を確認
特定の値に鋭いスパイク タイムアウト設定値や外部連携の固定待ちが疑われる 該当区間の棒をクリックして個別トランザクションを確認

パーセンタイル基準線

グラフ上の垂直線は各パーセンタイルの位置を示します。 P99 (赤) より右側にある棒が、いわゆるテールレイテンシです。

  • P50 (中央値) — 半数のユーザがこれより速い。「典型的な体験」
  • P90 — 10 リクエストに 1 回はこれより遅い
  • P99 — 100 リクエストに 1 回。1 画面が 20 リソースを読むなら、1 画面あたり約 2 割が P99 を踏む計算になります
平均値は分布の中に線として現れません。平均と P50 が大きく離れている場合、 それ自体が「一部の極端に遅いトランザクションが平均を押し上げている」証拠です。

オーバーフロービン (オレンジの棒)

横軸の上限は P99.5 を基準に自動決定します。極端な外れ値に軸全体を支配させないためです。 上限を超えたトランザクションは最終ビンに合算され、オレンジ色で表示されます。 この棒が目立つ場合は、テールが想定以上に長いことを意味します。

ビンモードと Y 軸ログ

  • 自動 (50ms間隔) — 既定。ビン幅は 50ms 固定、上限は P99.5 を 50ms の倍数へ切り上げ。X 軸の目盛りとガイド線はビン境界 (0 / 50 / 100...) に引かれます
  • ログスケール — 1ms 〜 60s のようにレンジが 3 桁以上開く場合に使用
  • 手動 — ビン幅と上限を固定。チューニング前後を比較する際は必ず手動で軸を揃えてください
  • Y 軸ログ — テール側の「件数が少ないが重要な」棒を見えるようにします

3. パーセンタイル曲線 (CDF)

横軸がパーセンタイル (0〜100)、縦軸が応答時間です。 「上位 X% のユーザは何 ms 以内で応答を得られているか」を連続的に示します。

  • なだらかな右上がり — 応答時間が安定。テールリスクは低い
  • P99 付近で急激に立ち上がる「崖 (cliff)」 — ごく一部だけが極端に遅い。 タイムアウト、リトライ、GC ストップザワールドなどが典型的な原因です

「テール拡大」をオンにすると P90 以降だけを拡大表示します。 崖の立ち上がり位置を特定するのに有効です。

4. アプリケーション別 P99 TOP10

applicationName ごとにグループ化し、P99 が大きい順に 10 件表示します。 全体の P99 を押し上げている「犯人」を特定するための入口です。

棒をクリックすると、そのアプリケーションのみでヒストグラムを再描画します (ドリルダウン)。 ドリルダウンはアプリケーション名の完全一致です。 一方、「アプリケーション」入力欄での絞り込みは部分一致です (例: /api/user と入力すると /api/user/profile も対象になります)。 ESC キーまたは「解除」ボタンで全件表示に戻ります。

なお、サンプル数が極端に少ないアプリケーションの P99 は統計的に不安定です。 本ランキングは 5 件以上のサンプルがあるアプリケーションのみを対象としています。

5. よくある質問

Q. 照会に時間がかかります

1 分チャンクを逐次で取得するため、1 時間の照会は 60 回の API 呼び出しになります。 120 回を超える場合は、実行前に確認ダイアログが表示されます。 期間バッジに表示されるチャンク数を目安にしてください。 進捗バーの「中断」ボタンで、その時点までのデータを使って分析を確定できます。

Q. 「標本上限に到達しました」と表示されました

ブラウザのメモリを保護するため、累積 30 万件で収集を打ち切ります (public/pd/config.js の MAX_POINTS で変更可能)。 期間を狭めるか、インスタンスで絞り込んでから再照会してください。

Q. 「標本不足」と表示されます

サンプル数が 1,000 件未満の場合に表示されます。 P99 は上位 1% の値なので、1,000 件未満では実質的に数件の観測値だけで決まってしまい、 統計的な信頼性が低くなります。期間を広げてから判断してください。

Q. 一部のチャンクが失敗しました

各チャンクは最大 2 回リトライした後、失敗した場合はスキップして続行します。 分布の一部が欠損している状態なので、件数の絶対値ではなく形状の傾向としてご覧ください。 頻発する場合は、config.js の CHUNK_WAIT_MS に 100〜500 を設定して データサーバへの負荷を下げると改善することがあります。

Q. 期間の入力欄の時刻が、自分の PC の時刻と違います

入力欄の時刻は JENNIFER サーバの時間帯 (入力欄の横の JST など) で表示しています。 ブラウザの時間帯と異なる場合は、サーバの時刻に換算して表示・照会されます。 ブラウザのローカル時刻で扱いたい場合は、config.js の TIMEZONE を空にしてください。

Q. 「JENNIFERサーバに接続できませんでした」と表示されます

すべてのチャンクの取得に失敗した状態です。ネットワークと API プロキシの設定 (トークンを含む) をご確認ください。 運用環境ではダミーデータを表示せず、サンプル数は 0 のままになります (実データと誤認しないためです)。 開発サーバ (npm run dev) に限り、画面の動作確認用にモックデータを表示し、 「実データではありません」と警告します。

Q. 「取得済みの N 件のみを表示しています (不完全なデータです)」と表示されます

収集の途中で認証エラー (401) などが発生した場合です。それまでに取得できた実データは破棄せず、そのまま表示します。 ただし期間の一部が欠けているため、件数の絶対値ではなく形状の傾向としてご覧ください。

Q. 「チャンク境界で重複していた N 件を除外しました」と表示されます

異常ではありません。API が境界時刻を両側で含んで返したため、同じトランザクション (txid) が 隣り合う 2 つのチャンクに現れ、重複分を 1 件として数えるよう除外したことをお知らせしています。

Q. 指定した開始時刻より前のトランザクションが含まれています

仕様どおりの動作です。この API は当該区間に終了したトランザクションを返すため、 区間をまたいで実行された長時間トランザクションも取りこぼさずに捕捉されます。 テール分析においてはむしろ望ましい挙動です。
