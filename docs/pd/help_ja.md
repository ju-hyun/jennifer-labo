# 分析ガイド (日本語原稿)

> `pd/help.html` の原稿。HTML を修正する際はこのファイルも併せて更新すること。

## 1. システム概要

本ツールは JENNIFER5 が収集した **X-View トランザクション点データ**を OpenAPI 経由で取得し、
応答時間の**分布**を可視化します。集計済みの平均値を扱う「性能トレンド分析 (PTA)」とは異なり、
個々のトランザクション 1 件 1 件を 1 つの点として扱います。

### なぜ平均値では不十分なのか

平均応答時間 150ms のシステムでも、P99 が 800ms であれば
**100 リクエストに 1 回は 5 倍以上遅い体験**が発生しています。
平均値は分布の裾 (テール) を隠してしまうため、実際のユーザ体験を代表しません。
SLA / SLO は平均ではなくパーセンタイルで定義すべきです。

### データ取得の仕組み

X-View データの取得には OpenAPI の `/api/transaction/time` を使用します。
この API は仕様上 **1 回の照会で最大 1 分間**しか取得できないため、
指定した期間を 1 分単位のチャンクに分割し、**逐次 (同時実行数 1)** で取得します。

> X-View の照会は JENNIFER のデータサーバに負荷をかけます (マニュアル付録 5.9.4.5 に明記)。
> 意図的に並列化していないのはこのためです。期間はできる限り絞り込んでご利用ください。

「直近 N 分」のプリセットは、**「照会」ボタンを押した時点の現在時刻**で期間を取り直します
(画面を開いたまま時間が経っても、古い区間を照会しません)。照会回数が 120 回 (= 120 分) を超える場合は、
実行前に確認ダイアログを表示します (`config.js` の `CONFIRM_CHUNKS` で変更可能)。

隣り合うチャンクは境界の時刻を共有します。API が境界時刻を両側で含む場合、境界で終了したトランザクションが
2 回返されることがあるため、直前のチャンクと `txid` が同じ行は自動的に除外し、除外した件数を画面に通知します。

期間の時刻は **JENNIFER サーバの時間帯**（`config.js` の `TIMEZONE`。配布時の既定は `Asia/Tokyo`）で指定・表示します。入力欄の横に `JST` などと表示されます。ブラウザの時間帯がサーバと異なる場合（例：海外から日本のサーバを見る場合）でも、サーバ基準の時刻で照会されます。`TIMEZONE` を空にすると、従来どおりブラウザのローカル時刻になります。

### 対象の絞り込み

| 絞り込み | 実行場所 | 理由 |
| :--- | :--- | :--- |
| ドメイン | API 側 | `domain_id` は必須パラメータ |
| インスタンス | API 側 | `instance_id` パラメータで指定 |
| ビジネス | クライアント側 | API に該当パラメータが無いため、取得済みデータの `businessId` 配列で判定 |
| エラー / アプリケーション名 | クライアント側 | 再照会せずに即時再計算されます |

## 2. メインヒストグラム

横軸が応答時間の区間 (ビン)、縦軸がその区間に入ったトランザクション件数です。

### 分布の形の読み方

| 形状 | 意味 | 次のアクション |
| :--- | :--- | :--- |
| 左に鋭いピーク + 右にロングテール | 正常な Web システムの典型 | テールの原因 (GC / ロック / 遅い SQL) を特定 |
| 山が 2 つ (二峰性) | 2 種類の処理が混在 | アプリケーション名で絞り込んで山を分離 |
| 全体的に平坦で広い | 応答時間が安定していない | PTA で同時刻の CPU・TPS 推移を確認 |
| 特定の値に鋭いスパイク | タイムアウト設定値や外部連携の固定待ち | 該当区間の棒をクリックして個別トランザクションを確認 |

### パーセンタイル基準線

- **P50 (中央値)** — 半数のユーザがこれより速い。「典型的な体験」
- **P90** — 10 リクエストに 1 回はこれより遅い
- **P99** — 100 リクエストに 1 回。1 画面が 20 リソースを読むなら、1 画面あたり約 2 割が P99 を踏む

> 平均値は分布の中に線として現れません。平均と P50 が大きく離れている場合、
> それ自体が「一部の極端に遅いトランザクションが平均を押し上げている」証拠です。

### オーバーフロービン (オレンジの棒)

横軸の上限は P99.5 を基準に自動決定します。上限を超えたトランザクションは
**最終ビンに合算**され、オレンジ色で表示されます。

### ビンモードと Y 軸ログ

- **自動 (50ms間隔)** — 既定。ビン幅は 50ms 固定、上限は P99.5 を 50ms の倍数へ切り上げ
  (X 軸の目盛りとガイド線はビン境界 = 0 / 50 / 100... に引かれます)
- **ログスケール** — レンジが 3 桁以上開く場合に使用
- **手動** — チューニング前後を比較する際は必ず手動で軸を揃えること
- **Y 軸ログ** — テール側の低い棒を見えるようにする

## 3. パーセンタイル曲線 (CDF)

横軸がパーセンタイル、縦軸が応答時間です。

- **なだらかな右上がり** — 応答時間が安定。テールリスクは低い
- **P99 付近で急激に立ち上がる「崖」** — タイムアウト、リトライ、GC ストップザワールドが典型

## 4. アプリケーション別 P99 TOP10

`applicationName` ごとに P99 が大きい順に 10 件表示。棒クリックでドリルダウン (アプリケーション名の**完全一致**)、`ESC` で解除。
「アプリケーション」入力欄での絞り込みは**部分一致**です (例: `/api/user` は `/api/user/profile` も対象)。
サンプル数 5 件以上のアプリケーションのみが対象です。

## 5. よくある質問

**Q. 照会に時間がかかります** — 1 時間の照会は 60 回の API 呼び出しになります。120 回を超える場合は実行前に確認ダイアログが出ます。
チャンク数バッジを目安に、「中断」ボタンで途中確定もできます。

**Q. 「標本上限に到達しました」** — 累積 30 万件で打ち切ります (`config.js` の `MAX_POINTS`)。

**Q. 「標本不足」と表示される** — 1,000 件未満では P99 が数件の観測値で決まり信頼性が低いためです。

**Q. 一部のチャンクが失敗しました** — 2 回リトライ後スキップします。
頻発する場合は `CHUNK_WAIT_MS` に 100〜500 を設定してください。

**Q. 期間の入力欄の時刻が、自分の PC の時刻と違う** — 入力欄の時刻は JENNIFER サーバの時間帯（入力欄の横の `JST` など）で表示しています。ブラウザの時間帯と異なる場合は、サーバの時刻に換算して表示・照会されます。ブラウザのローカル時刻で扱いたい場合は、`config.js` の `TIMEZONE` を空にしてください。

**Q. 「JENNIFERサーバに接続できませんでした」と表示される** — 全チャンクの取得に失敗した状態です。ネットワークと API プロキシ (トークン含む) を確認してください。
運用環境ではダミーデータを表示しません (実データと誤認しないため)。開発サーバ (`npm run dev`) のみ、確認用にモックデータを表示し警告します。

**Q. 「取得済みの N 件のみを表示しています (不完全なデータです)」と表示される** — 収集の途中で認証エラー (401) などが起きた場合です。
取得済みの実データは破棄せず表示しますが、期間の一部が欠けているため形状の傾向としてご覧ください。

**Q. 「チャンク境界で重複していた N 件を除外しました」と表示される** — 異常ではありません。API が境界時刻を両側で含んで返したため、
同じ `txid` が隣り合う 2 チャンクに現れ、重複分を除外したことの通知です。

**Q. 指定した開始時刻より前のトランザクションが含まれる** — 仕様どおりです。
この API は**当該区間に終了した**トランザクションを返すため、区間をまたぐ長時間 TX も捕捉されます。
